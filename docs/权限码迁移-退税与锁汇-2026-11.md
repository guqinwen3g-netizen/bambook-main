# 权限码迁移：退税改用 tax:*，锁汇改用 fx:lock（2026-11）

## 改了什么

| 动作 | 原判定码 | 新判定码 |
| --- | --- | --- |
| 查看出口退税记录（读投影 `exportRebate`） | `invoices:read` | `tax:read` |
| 登记 / 作废退税率、登记退税申报、撤回申报（`rebate.rate.*`、`rebate.claim.file`、`rebate.claim.withdraw`） | `invoices:write` | `tax:write` |
| 登记税务核准（`rebate.claim.approve`） | `invoices:write` | `tax:approve` |
| 退税到账勾稽与冲回（`rebate.claim.receive`、`rebate.claim.reverseReceipt`） | `invoices:reconcile` | 不变 |
| 登记锁汇（`finance.fx.lock`） | `vouchers:write` | `fx:lock` |
| 结汇、结汇分配、冲回（`finance.fx.settle/allocate/reverse`） | `vouchers:write` | 不变 |

**计税依据 `sensitive:tax_base`**：退税申报、税务核准、退税到账勾稽（`rebate.claim.file`、`rebate.claim.approve`、`rebate.claim.receive`）在上表判定码之外另须持有 `sensitive:tax_base`，否则返回 403。这三项的输入、预演和错误提示都直接含应退、核准或到账金额。默认岗位里能办这三项的财务、管理员，以及前端「出纳」「会计」模板都持有该码。不持该码的账号读取时，进项税额、税率、计税金额，以及应退、核准、到账退税额一律显示为“已隐藏”。退税事件、预演事件、Agent 提议说明、Agent 审计原始填写和退税命令的错误提示里的金额，按同一规则替换为“已隐藏”。被退税勾稽占用的国库到账流水不下发；只要存在这类流水，公司银行账户也一并隐藏。

## 岗位默认矩阵（新默认值）

为保持系统岗位原有能力，默认矩阵（`lib/rolePermissionMatrix.ts` 与 `server/src/_shared/rolePermissionMatrix.ts`，两份一致）本次补授：

| 岗位 | 补授 | 原因 |
| --- | --- | --- |
| 公司管理员 `role-admin` | `customs:admin` | 印章 / 签章配置改按 `customs:admin` 判定，管理员原本就能管理印章 |
| 业务员 `role-sales`、销售主管 `role-sales-manager`、后勤 `role-logistics` | `tax:read` | 原先凭 `invoices:read` 能看退税记录；计税金额、税额、应退 / 核准 / 到账退税额仍按 `sensitive:tax_base` 隐藏 |
| QC `role-qc`、后勤 `role-logistics` | `ai:write:medium` | AI 写入按风险三级确认，原先能确认的中风险提议保持可确认 |
| 财务 `role-finance`、销售主管 `role-sales-manager` | `ai:write:high` | 高风险（付款、核销、审批）须持本码并复验登录密码 |

其余不变：财务岗原本持有 `tax:read/write/approve` 与 `fx:lock`；管理员持有 `tax:read`、`tax:approve`（没有 `tax:write`），改码后可以登记税务核准，这是矩阵原有设计（GAP-R11「退税申报审批」）生效；业务员保持 `ai:write:low` 与 `ai:write:medium`。

**单证模板写入改由 `customs:admin` 把关**（缺口 fin74）：原先持 `customs:write` 即可改单证模板，现在只有后勤 / 单证与公司管理员可改；业务员、销售主管不补授。运行中的 Mist 前端没有单证模板编辑入口，这一变化目前只影响直接调用接口。

## 已存在公司须运行补授脚本

公司系统岗位是每家公司各自的副本（`<code>@<companyId>`），开通时按当时的默认矩阵建立，之后**不会**随默认矩阵或 `npm run seed:base` 更新。老公司不补授时，管理员拿不到 `customs:admin`（印章增改删失效），上表的补授也到不了。

脚本 `server/scripts/backfill-p0-role-permissions.ts` 只补上表清单，不按默认矩阵整体同步（公司有意撤销的旧权限不会补回），不删除任何权限，不改自定义岗位：

1. 先备份数据库；
2. 预演：`cd server && npx tsx scripts/backfill-p0-role-permissions.ts`（可加 `--company <slug>`，可重复），核对打印的计划；
3. 写入：同一命令加 `--apply`。**不加 `--company` 时 `--apply` 会写入所有租户（全部公司）**，执行前须经用户授权（本次上线已获用户授权）；每家公司一个事务；缺少的权限码行先建；同一次上线内重复执行不重复写；
4. 写入后在管理员账号实测印章编辑，在财务账号实测退税申报与锁汇登记。

**只在本次上线后运行一次。** 脚本按清单补齐缺少的码，看不出缺少的码是“尚未补授”还是“公司之后有意撤销”。上线补授完成后，如果公司在岗位里有意撤销了清单中的某个码，不要再运行本脚本，否则会把它补回来。

**在开发服务器（腾讯云 bambook-dev）上运行**：在当前版本的 server 目录下先加载发布脚本所用的后端环境文件，再运行。路径以 `scripts/deploy/bambook-dev-release.sh` 为准：环境文件 `/etc/bambook-dev/backend.env`，当前版本 `/srv/bambook-dev/current`；发布时已在 server 目录安装含开发依赖的依赖，`npx tsx` 可直接用。

```
cd /srv/bambook-dev/current/server
set -a; . /etc/bambook-dev/backend.env; set +a
npx tsx scripts/backfill-p0-role-permissions.ts            # 预演
npx tsx scripts/backfill-p0-role-permissions.ts --apply    # 核对预演并备份后写入
```

环境文件属主为 `root:bambook-deploy`、权限 `0640`，须用能读取它的运维账号运行，不要打印文件内容（见 `docs/ops/dev-server-access.md`）。**正式环境（Mac mini、`jiangsupanda.com`）不适用这一通道**，须用户另行授权后按正式环境的方式执行。

输出只含公司标识、岗位码与权限码，例如：

```
[demo-co] 补授 8 项，需人工核对 6 项
  + role-admin@<companyId> customs:admin
  + role-sales@<companyId> tax:read
  ? custom-docs 持 customs:write 无 customs:admin
```

## 需要人工核对的自定义岗位

脚本以 `?` 行列出持旧码而没有对应新码的自定义岗位，改码后可能丢能力：

| 持有 | 缺少 | 影响 |
| --- | --- | --- |
| `invoices:read` | `tax:read` | 不能再查看退税记录 |
| `invoices:write` | `tax:write` | 不能再办理退税申报 |
| `vouchers:write` | `fx:lock` | 不能再登记锁汇 |
| `customs:write` | `customs:admin` | 不能再改单证模板与印章 |
| `tax:write` | `sensitive:tax_base` | 不能再登记退税申报 |
| `tax:approve` | `sensitive:tax_base` | 不能再登记税务核准 |
| `invoices:reconcile` | `sensitive:tax_base` | 不能再做退税到账勾稽（其他核销不受影响） |

由公司管理员在「公司管理 → 岗位」里逐个判断：确需该能力的岗位勾选对应权限（退税查看 / 录入，需要登记税务核准的再勾「退税申报提交审批」；锁汇勾「汇率锁定（远期结售汇）登记/分配」；单证模板勾报关与单证的审批档；办理退税申报、核准或到账勾稽的岗位勾「敏感-进项税/退税计税底值 查看」）。不需要的保持不勾。

## 已知限制

- **专票原件附件不掩码**：`sensitive:tax_base` 只作用于结构化字段（税额、税率、计税金额、应退 / 核准 / 到账退税额及其文字）。供应商票据的原件附件（增值税专票扫描件或 PDF）是付款核对必需的凭证，能查看应付票据的人照常可见，票面上的税额和税率也在其中。这是有意接受的取舍（2026-11 复核裁定）。
- **勾稽前的国库到账流水不隐藏**：退税到账流水只有在勾稽到退税申报之后才能识别为退税款，因而被隐藏。导入后、勾稽前，它与其他到账流水一样按现有收款权限可见，金额和付款方（如“国家金库”）都可看到。
