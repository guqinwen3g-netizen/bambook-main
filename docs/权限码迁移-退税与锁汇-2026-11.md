# 权限码迁移：退税改用 tax:*，锁汇改用 fx:lock（2026-11）

## 改了什么

| 动作 | 原判定码 | 新判定码 |
| --- | --- | --- |
| 查看出口退税记录（读投影 `exportRebate`） | `invoices:read` | `tax:read` |
| 登记 / 作废退税率、登记退税申报、撤回申报（`rebate.rate.*`、`rebate.claim.file`、`rebate.claim.withdraw`） | `invoices:write` | `tax:write` |
| 登记税务核准（`rebate.claim.approve`） | `invoices:write` | `tax:approve` |
| 退税到账勾稽与冲回（`rebate.claim.receive`、`rebate.claim.reverseReceipt`） | `invoices:reconcile` | 不变 |
| 登记锁汇（`finance.fx.lock`） | `vouchers:write` | `fx:lock` |
| 结汇、结汇分配、冲回（`finance.fx.settle/allocate/reverse`） | `vouchers:write` | 不变 |

## 岗位默认矩阵

不需要改默认矩阵，系统岗位原本能做的仍能做：

- 财务岗（`role-finance`）本来就持有 `tax:read`、`tax:write`、`tax:approve`、`fx:lock`，退税与锁汇照常办理。
- 业务员、销售主管、QC、后勤原先没有 `invoices:write` / `vouchers:write` 用于退税与锁汇，改码后同样没有。
- 公司管理员岗（`role-admin`）持有 `tax:read`、`tax:approve`，没有 `tax:write`。改码后仍可查看退税记录，并**新增可以登记税务核准**（原先因没有 `invoices:write` 做不了）。这是矩阵原有设计（GAP-R11「退税申报审批」）生效，不是新增授权。

## 需要人工核对的情况

自定义岗位（岗位编辑器里新建或改过的岗位）如果只勾了「发票创建」(`invoices:write`) 而没有勾退税相关权限，改码后**不能再办理退税申报**；只勾了「收付款凭证录入」(`vouchers:write`) 而没有勾「汇率锁定」(`fx:lock`)，改码后**不能再登记锁汇**。

上线前请公司管理员在「公司管理 → 岗位」里逐个核对自定义岗位：

1. 需要办理退税的岗位，勾选「出口退税申报查看」「退税申报录入」，需要登记税务核准的再勾「退税申报提交审批」；
2. 需要登记锁汇的岗位，勾选「汇率锁定（远期结售汇）登记/分配」。

系统岗位由 `npm run seed:base`（`seed-rbac.ts` 按默认矩阵写入岗位权限）同步。若生产库的系统岗位是在 `tax:*` / `fx:lock` 加入矩阵之前播种、之后没有重跑过，请先重跑一次再上线，并在财务账号上实测能打开退税申报和锁汇登记。
