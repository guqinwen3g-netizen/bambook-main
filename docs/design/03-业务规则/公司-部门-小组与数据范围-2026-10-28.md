# 公司 · 部门 · 小组与数据范围（2026-10-28 定案）

> 取代：[小组与业务数据共享（DR-042 v2.2）](小组与业务数据共享.md) 中与本文冲突的部分（切换器定位、部门不参与数据范围、面料/成衣业务组）。DR-042 的软撤销、审计留痕、失效优先级仍沿用。
> 依据：2026-10-19 组织模型定案（GO-LIVE §1）；2026-10-28 用户对话确认（本文「已确认」各条）。
> 状态：规则已确认；§3.2 细粒度范围为本文提出的方案，待用户确认后进入实施；实现按 §6 分期，当前全部未实现。

## 1. 已确认规则

| # | 规则 |
|---|---|
| R1 | **一家公司 = 一个公司库**。不存在同一公司的第二个库，也不存在个人空间、空间切换、空间回收站。“工作空间”只作为迁移期的底层存储名。 |
| R2 | **进入公司 = 公司成员资格**（在职且启用的公司成员）。不再由所有者逐账号“授权进入”。看到哪些模块仍由岗位权限决定，看到哪些记录由 §2 数据范围决定。 |
| R3 | **小组**：名称自定义；一个人可在多个组。左上角可切换“看哪一组”，并保留“全部”。切换只改变视角，不改变权限（权限永远是各组并集）。 |
| R4 | **小组协作范围以客户为准**：把客户放进小组，该客户的业务即由小组共同推进。 |
| R5 | **数据范围**：本人负责/经手 ∪ 所在小组 ∪ 部门领导看本部门及下级部门成员的业务 ∪ 总经理、老板、管理员与专业岗位（财务、QC、后勤、单证等）按模块看全公司。未入组只看本人。 |
| R6 | **档案是公司共享资料**：客户、供应商、产品/数字档案全公司可查（防重复建档、知道找谁对接）；敏感字段按既有遮罩。订单、报价、跟进、采购、履约等业务记录按 R5。 |
| R7 | **面料/成衣不再卡人**：业务员通用，可同时做面料和成衣。**主管按业务线划分管理权**：面料主管对全部面料订单、采购、开发、履约有管理权；成衣主管同理。 |
| R8 | 组长可选（10-19 定案不变）：首个生产案例不设组长，审批交部门领导或总经理；禁止自批。 |

## 2. 数据范围合成

```
可见业务记录(用户) =
    岗位为全公司范围（老板/总经理/管理员/专业岗位）       → 该模块全部
  ∪ 本人是负责人或经手人的记录
  ∪ 所在小组协作范围内的记录（§3）
  ∪ 作为部门领导：本部门及下级部门在职成员负责/经手的记录
  ∪ 作为业务线主管：本业务线的全部记录（§4）
```

- 业务记录的“负责人”以**客户跟进人/订单负责人**为锚，下游单据（采购合同、生产、质检、出运、单证、发票、收款核销、索赔）随所属订单可见，不各自判断。
- 模块权限先过滤（没有财务读权限的人，即使在组内也看不到收款）；数据范围只在模块内再按记录收窄。
- 动态、待办、通知、日历、附件、搜索、报表汇总、AI 助手读取，全部按同一结果裁剪；报表只统计可见记录。
- 写入 = 岗位写权限 ∧ 记录可见 ∧ 各业务规则（审批、禁止自批不变）。

## 3. 小组协作范围

### 3.1 整户客户（R4，已确认）

客户进组后，该客户名下**现有及以后新增**的全部业务对组员可见并可协作。

### 3.2 单笔业务与“项目”（方案，待确认）

一个客户常有多笔业务，不一定都归小组。范围条目因此有两种：

| 条目 | 含义 |
|---|---|
| 整户客户 | §3.1 |
| 单笔业务 | 一个商机、开发案、报价或订单，只共享这一条业务链 |

- **“项目”就是小组本身**：为某个季度系列、某个大单或某个专项建一个小组，把相关的几笔业务（可跨客户）挂进来；项目结束即解散小组，历史留痕。不另建“项目”对象。
- **链路延伸**：单笔订单进组，其下游单据全部跟随；其来源（报价、开发案、商机）作为只读上下文可见。组内的商机/报价/开发案转成订单时，新订单自动留在组内。
- **同客户其他业务不受影响**；客户档案本来全公司可查（R6）。
- **组内新建**：左上角选中某个小组时新建业务，表单默认“归入当前小组”，可取消；整户客户的新业务自动进入。
- 一笔业务可在多个组；移出范围或退组即时失效，授权与撤销留审计。

### 3.3 谁能管理

| 动作 | 允许 |
|---|---|
| 建组、改名、解散、加减成员 | 部门领导、业务线主管、总经理/管理员；启用的组长管本组成员 |
| 把客户/业务放进小组或移出 | 该业务负责人，及其上级（部门领导、业务线主管、总经理/管理员）；组员不能把别人的业务拉进组 |
| 组员 | 可见 + 按本人岗位权限协作（跟进、待办、经手办理）；负责人不因进组改变 |

## 4. 面料 / 成衣业务线（R7）

- 记录的业务线由记录自身决定：订单类型、开发案类型、采购/加工合同的业务域、内部发料域。客户不分线。
- **主管岗位**在账号上设置“管理业务线”（面料、成衣，可多选）。主管对本线全部记录可见，并有本线的审批、督办、改派、交接等管理权。
- 业务员不再设置业务组；经手人、负责人选择不再按面料/成衣校验。
- 现有“审批资格”（面料/成衣订单审批负责人、4 项供应商承诺审批人）保留按线配置，须与主管的管理业务线一致。
- 现状替换：公司库内的 `memberGroups`（面料/成衣业务组）退出，主管的管理业务线进入账号/岗位资料。

## 5. 左上角小组切换器

- 显示当前视角：某个小组 / 全部；未入组显示部门。
- 展开为轻量浮层：小组列表（名称、成员数）、“全部”、公司资料入口；有权者另有“管理小组”。
- 切换即时生效，不整页刷新：列表、首页、待办按视角筛选；选择记忆到个人偏好。
- 视觉与动效按当前 Mist 最高标准：浮层展开/收起、选中态过渡、键盘可达、减少动态效果时降级；实际浏览器同视口目视核对。
- 列表与详情：组内共享来的记录带弱化来源标记（小组名）；详情可看“共享至”的小组，有权者就地增减。

## 6. 实施分期

| 期 | 内容 | 验收 |
|---|---|---|
| P1 一公司一库 | 公司库按公司唯一（数据库约束+迁移前核对）；进入按公司成员资格；移除新建库、切换、回收站、逐账号授权进入；开户同时建库；本机演示保持一个演示公司 | 同公司第二个库无法产生；离职/停用即不能进入；越公司 404；既有数据不变 |
| P2 小组数据 | 人事小组为唯一小组概念；协作范围条目（整户/单笔）存储、增删、审计；API | 服务端权限与审计测试 |
| P3 行级裁剪 | 读投影按 §2 裁剪全部业务集合及其派生（动态/待办/通知/附件/搜索/报表/助手）；写侧同规则 | 7 岗位 × 越权读写矩阵测试，逐条“读不到、改不了” |
| P4 业务线主管 | 管理业务线设置；去掉业务员面料/成衣限制；主管按线管理 | 跨线业务员可办理；主管跨线无管理权 |
| P5 切换器与界面 | §5 | 浏览器实看，深浅色与常用宽度 |
| P6 真实走查 | 隔离租户按老板、部门领导、面料主管、成衣主管、业务员（组内/未入组）、财务、QC、后勤走一遍 | 如实记录未覆盖项 |

## 7. 当前实现（2026-10-28，main `e145e62`）

- 公司库：`MistWorkspace` 有 `companyId`，但不唯一；首次进入未被授权时会为个人新建一个库（`server/src/mist/repository.ts` `create`/`activeWorkspace`）；仍有新建、列表、回收站、`memberIds` 授权接口（`server/src/mist/route.ts`）。
- 读投影：`server/src/mist/access.ts` `projectState` 只按模块权限裁剪，模块内全公司可见；仅邮箱按个人隔离。
- 小组：人事 `Team/TeamMember` 只用于左上角显示（`organizationContext.ts`），不影响数据；`TeamDataGrant` 只接在旧客户档案服务。
- 面料/成衣：`state.memberGroups`（`server/src/shared/mistAccounts.ts`）限制经手人选择、主管团队视角与内部发料。
