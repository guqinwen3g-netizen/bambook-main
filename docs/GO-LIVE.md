> **本文件是当前项目方向、用户定案、进度和待办的唯一权威记录**（业务规则细节、技术资料仍按 [文档导航](README.md) 查对应真源；与本文件冲突时以本文件为准）。 2026-10-18 起由 Notion“上线推进 / 总协调 / To Do List”迁入仓库，Notion 原页面只作历史参考，不再更新、不再作为依据。之后每完成一块工作，只更新本文件“进度记录”和“下一步”。
>
> 接手顺序：先读 [AGENTS.md](../AGENTS.md)（工作方式）→ 本文件（方向与停点）→ 按任务查 [文档导航](README.md)。

## 1. 用户定案（2026-10-17 / 10-18）

- **目标**：把软件本体做完整，达到公司可实际投入生产运行，越快越好。部署环境暂不考虑（将来后端放公司电脑、前端客户端 + 自有域名）。
- **单线接力**：不再有总协调与多 Agent 分工。当前接手的 Agent 自己判断优先级、自己实现、自己测试、自己合入 main。**不要让用户选方向**；按“上线必需、能直观感到基础完善”的优先级自主推进；不做额外附加功能。
- **节奏**：每完成一小块就提交 PR 合入 main（merge commit），避免进度丢失；不等 CI、不轮询 CI（CI 由系统自动跑，下次开工时若 main 的 CI 失败先修）。
- **数据**：全新系统，**不兼容任何旧数据**；开发 / 测试一律模拟数据，需要时直接改种子与演示数据。
- **业务规则**：按外贸纺织服装行业最专业、最权威的做法自主判断；首版按此上线，特殊需求放第二版微调。旧讨论文档只作业务参考，互相冲突以最新为准，不当教条。
- **外部对接**：邮件要接通（已接通 IMAP/SMTP）；银行流水、邮费 / DHL 等不做 API 对接，由业务 / 财务上传截图、凭证或按月汇总逐笔登记。
- **仍须先问用户**：正式环境（Mac mini、`jiangsupanda.com`）、真实数据或真实资金、对外发送（真实客户 / 供应商邮件等）。不绕过自动审核或权限拒绝。
- **仓库已公开**：任何密钥、真实客户 / 资金信息、服务器私有地址细节都不能入库。

## 2. 岗位模型

- **业务员**：承担绝大部分业务——客户联系、开发 / 样品、报价、订单跟单、询价比价等（外贸公司不设市场专岗，业务员有 marketing:write、pricing:write）。
- **主管 / 组长 / 部门主管**（面料部、服装部）：本身也是业务员，另有更高的审批与决策权（审批、团队视角、督办、客户交接）。
- **财务**：登记并执行业务提交的收付款与单据，负责对账。
- **QC**：样品与大货评审确认；面料 QC 与服装 QC 完全独立。
- **后勤**：储运与后勤单据（订舱、装箱、报关）。
- **领导**：经理、总经办。
- 本地演示有 6 个经办人身份：顾言（业务·服装部）、沈禾（业务·面料部）、周敏（业务主管）、许言（QC）、陈晓（后勤）、林舒（财务），共用一个演示空间。

## 3. 已确认的业务规则（不要再当成待决定）

- 面料寻样与面料开发是独立需求、不互转。
- 开发：有保留通过可确认、留档、转档并提示关注项；不收费开发在需求方认可后结案。
- 订单：颜色尺码 / 面料规格、数量变更审批及下限、溢短装比例与经理审批、草稿作废、批准后取消。
- 报价：部分条目转单、正式报价 PDF、管理层设最低毛利率、低于 MOQ 提示。
- 风险：业务员只处理本人客户 / 订单风险并可关闭低风险；高风险关闭、豁免及带风险放行需经理审批；信用冻结客户出运离港须部门主管批准“带风险放行”，每次只放行一票。
- 报表：实际结汇 / 月末暂估 / 定价预计三口径并列，暂估须标识；不含 / 含退税毛利并列，退税到账比对差异。
- 人事：只做员工档案、组织架构、账号、岗位；请假 / 外出、考勤、绩效、薪资明确不做。
- 用户已取消：部分收货合同短结后剩余数量转给其他供应商。

## 4. 工作方式（每一块工作）

1. 从 main 拉最新，在工作分支（历来用 `golive`）上开发。
2. 改动前按 AGENTS.md 读必要源码与 Mist 前端规范（`.qoder/skills/bambook-ui/SKILL.md`）。
3. 完成后跑完整本地测试：`npm test`（前端）、`cd server && npm run test:mist`（服务端）、`npx tsc -p tsconfig.mist.json --noEmit` 与 `npx tsc -p server/tsconfig.json --noEmit`（类型），`npm run mist:check`（Mist 规范）。约 5–8 分钟，输出落到文件只看摘要。
4. 推送 → 开 PR 到 main → 以 merge commit 合入（不 squash、不强推）。
5. 只改文档时：PR 只做空白检查，合入 main 后不跑检查、不部署，可不跑本地全量测试（跑 `npm run mist:check` 即可）。
6. 在本文件“进度记录”追加一行（PR 号、做了什么、测试数），并更新“下一步”。

基线（2026-10-19，代码截至 PR #175）：前端 1181 项、服务端 990 passed / 11 skipped，类型检查通过。管理后台路由测试不在 `test:mist` 内，改动 `server/src/admin` 时另跑 `cd server && npx vitest run src/admin`。`electron/brandAssets.test.ts` 有一条既有失败（引用不存在的临时路径），不在 `npm test` 范围内，可不管。
