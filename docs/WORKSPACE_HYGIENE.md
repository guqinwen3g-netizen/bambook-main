# Bambook 工作区卫生契约

本文件定义本仓库的本地工作区边界。它不替代业务数据保留、交付物归档或 Git 历史治理流程。

## 版本控制边界

- **必须纳入版本控制**：可从干净克隆构建、测试和运行产品所需的源码、配置、迁移、锁文件、公共运行时资源和权威文档。
- **只在本地保留**：依赖安装目录、构建输出、测试结果、浏览器会话抓取、日志、PID、调试输出和可再生成中间文件。
- **先判定归属再处理**：业务导出、原始导入数据、模型文件、设计探索、截图证据和协作笔记不得仅凭目录名删除；应分别归入产品源、外部审计档案或本地缓存。
- **地图中间物**：`tmp/gba/` 由 `docs/ZHANGJIAGANG_REAL_BUILDINGS.md` 的下载与构建步骤再生；产品运行时资源是受版本控制的 `public/data/*.pmtiles`，不能一并清除。

## 标准检查

在提交或交接前运行：

```bash
git status --short --branch
git ls-files -ci --exclude-standard
git status --ignored --short
```

`git ls-files -ci --exclude-standard` 必须为空；若非空，说明某文件已经被跟踪但现在又被 `.gitignore` 规则覆盖，需要通过迁移或 `git rm --cached` 明确完成索引治理。

## 清理方式

1. 先停止 Bambook 的开发、Electron 和测试进程。
2. 只清理 `.gitignore` 已明确覆盖、且可由依赖安装或构建重新生成的目录。
3. 对有交付或审计价值的文件先移到仓库外的受控归档位置；不要把它们留在 `tmp/`、`.dbg/` 或浏览器会话目录。
4. 清理后重新运行标准检查。需要验证运行能力时，再执行 `npm ci` 与相应的 build/test 命令。

## Git 历史治理

Git 对象库瘦身、不可达对象回收、分支删除和历史重写属于独立变更：必须先冻结所有 worktree、备份 refs/远端、确认协作者迁移窗口，再执行。不得与日常工作树清理混合进行。

## 已有其他任务占用原目录时

- 验收与既有文档任务使用各自管理工作树，分别安装锁定依赖，使用独立预览端口和 Vite 缓存。共享 Git refs 不等于可以切换、暂存、恢复或提交另一目录的工作。
- 应用切分支生成的自动暂存按准确提交恢复到自己的工作树；先保留私有补丁和备份，不直接 pop 或丢弃原暂存。
- 原 main 需要同步时，先核对待进入提交与该目录现有变更没有路径重叠，保存差异和文件摘要，再用 `--ff-only --no-autostash` 更新并核对原文件完整。出现重叠或非快进时保留现场，在独立工作树解决，不以 reset、强推或自动暂存替代隔离。
- 需要持续运行的本机预览及受限 SSH 转发由用户级服务保活，启动清单、日志与凭据仅留本机私有目录；归档工作树前先停用其对应用户服务。Vite 忽略 `dist`、`dist-*`、`out` 等构建输出，构建不应重载正在填写的业务表单。
- GitHub SSH 端口中断时先区分网络与授权，验证备用 443 路由仍使用既有身份和严格主机校验；仓库局部配置只作用于已核实的远端，若仍被网络间歇关闭，可用现有 GitHub 登录的 HTTPS 作为仓库局部传输，保留原配置私有备份，不以换密钥或关闭校验代替连通性修复。
