# 邮箱接入与自动收件 SOP

适用于「智能邮箱」中的已接入邮箱。示例邮箱只展示合成邮件，不连接邮件服务器。

## 岗位与办理条件

- 邮箱接入人具有邮件查看、办理权限，并已取得该邮箱的服务器地址、端口、加密方式、用户名和密码或授权码。
- 个人邮箱仅接入人可见；共享邮箱对接入人及指定成员可见。接入或修改共享邮箱的设置，还需要邮件账户管理权限。
- 共享成员可以按当前授权查看和办理邮件，但自动收件只能由接入人本人开启或关闭。不要借用其他人的账号。

## 接入邮箱

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 打开「智能邮箱」→「邮箱账号」→「接入邮箱」。 | 出现邮箱设置表单。 |
| 2 | 填写地址、名称、服务器、端口和加密方式；共享邮箱选择可见成员。 | 信息与邮件服务商提供的参数一致。登录用户名不同于邮箱地址时，单独填写。 |
| 3 | 填写密码或授权码，点击「保存并验证登录」。 | 系统实际验证收信和发信登录。成功后显示邮箱已连接，凭据不会回显。 |
| 4 | 在该邮箱下开启「自动收件」。 | 开关开启，状态显示「等待收件」或「收件中」。 |
| 5 | 返回邮箱列表，选择该邮箱查看来信。 | 新来信进入收件箱；需要立即核对时可点「同步」。 |

自动收件在服务器运行，不要求保持邮箱页面或浏览器打开。正常空闲时约每五分钟检查一次；有积压时分批补收。服务器重启后继续处理已开启的邮箱，不需要再次开启。邮件服务不可用或有积压时，新邮件可能稍后出现。

## 阅读来信与查找原件

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 在邮箱左侧选定要查看的邮箱，再选收件箱、星标等文件夹或视图。 | 列表只展示当前选择内的邮件；需要跨邮箱查找时选择「全部邮箱」。 |
| 2 | 输入主题、人员、正文或附件名等关键词，按需选择分类。 | 列表显示匹配记录。分类和摘要不能替代邮件原文。 |
| 3 | 打开列表中的邮件，核对发件人、收件人、正文与附件。 | 原邮箱选择、视图与搜索保留；在「未读」中打开邮件后，邮件可能从未读列表消失，阅读区仍显示原件。 |
| 4 | 返回邮件列表，或明确切换邮箱/文件夹。 | 返回列表保留原筛选；切换来源关闭旧阅读状态，不把上一封详情当成新邮箱的来信。 |

「示例」来源只用于演示，不能据此确认真实收发。真实邮箱中的邮件按各自来源及同步状态核对；不要把同一公司存在示例邮箱理解为其他已接入邮箱也不能收发。

## 暂停、重连与状态核对

| 情况 | 操作 | 结果与下一步 |
|---|---|---|
| 暂停后台收件 | 邮箱账号 → 关闭该邮箱的「自动收件」。 | 显示「已关闭」，已收到的邮件保留；仍可手动同步。关闭窗口或离开页面不会暂停收件。 |
| 密码或授权码变更 | 接入人选择「重新绑定凭据」，验证成功后核对并重新开启自动收件。 | 新凭据生效；旧收件授权不自动沿用到改变后的连接。 |
| 需要解除接入 | 接入人点击「断开」。 | 后台收件停止，保存的邮箱凭据解除；不删除已经导入的邮件。 |
| 显示「稍后重试」 | 查看错误及最近收件时间，等待重试；也可手动同步核对。 | 临时故障会自动延后重试，最长间隔约三十分钟。 |
| 显示「需要重新开启」 | 接入人核对当前公司与邮件权限、邮箱设置及凭据，再重新开启。 | 身份或授权已失效时不会继续以旧权限收件。 |
| 显示「收件服务未运行」 | 联系系统维护人员。 | 不反复点击开启；已经开启的登记仍保留，待服务恢复后续办。 |
| 显示「待核对」 | 点击「核对状态」；仍未确认时使用「重试」。 | 核对原操作结果，避免反复切换开关。 |
| 邮件超过大小上限 | 在原邮箱处理超过 64MB 的原件后再同步。 | 不以重复点击同步替代处理原件。 |

## 完成标准与业务交接

接入成功、自动收件开启、来信可读，是三个不同结果。首次接入后应确认能看到预期来信，不能只凭「已连接」判断收件已经完成。

收信不会自动确认订单、付款或修改业务单据。经办人阅读正文与附件，核对原件后，再在对应业务模块办理。需要主管或专业岗位接手时，交接相关单号、邮件与附件依据。

## 已读、星标与文件夹同步

已接入的真实邮箱中，已读、星标、归档、移回收件箱、移到已删除和恢复会提交到原邮箱。「重要」仍是 Bambook 内的标记。示例邮件只在系统内演示。

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 打开邮件，或使用邮件上方的已读、星标按钮。需要归档或恢复时使用对应按钮。 | 本地操作保存后显示「待同步原邮箱」或「同步原邮箱中」。这时不要把本地保存当作原邮箱已经完成。 |
| 2 | 等待同步回读。 | 成功后显示「原邮箱已同步」。归档和恢复仍是同一封邮件，原关联及附件保留。 |
| 3 | 在其他邮件客户端修改了标记或位置时，回到 Bambook 点击「同步」，或等待已开启的后台收件检查。 | 当前原邮箱状态回到系统；原邮箱中未找到的邮件保留本地副本，不自动删除。 |

关闭自动收件不会撤销已经提交的标记或移动操作。它们由同步服务继续处理，不要求保持页面打开。恢复邮件会返回删除前的位置，例如从归档删除的邮件恢复到归档。

## 同步失败与结果核对

| 状态或提示 | 处理方式 |
|---|---|
| 原邮箱同步失败 | 查看原因。临时连接故障会延后重试；需要立即核对时点击「重试同步」。 |
| 移动结果待核对 | 点击「重试同步」先核对原结果，不要再次点归档或删除。如果提示原移动没有完成，再决定重试，或选择「以原邮箱为准」。 |
| 以原邮箱为准 | 放弃本次尚未确认的本地修改，按能核实的原邮箱状态显示；此操作不移动或删除原邮箱的邮件。位置不明确时仍需先人工核对。 |
| 同步已暂停 | 当前账号、连接或权限可能已失效。提示邮箱登录失效时，请接入人核对密码或授权码并重新绑定。具有该邮箱办理权限的当前成员重新核对授权后，可以重试接续。 |
| 原邮箱不支持安全移动、未提供目标文件夹 | 在原邮箱办理或配置相应文件夹；不要反复点击。也可选择「以原邮箱为准」保留原位置。 |
| 邮箱来源已改变 | 旧来源邮件只作为历史副本保留，不能把它的操作发送到新邮箱。请在对应原邮箱中处理。 |
| 其他人已修改同一个标记 | 重新读取后核对双方修改，再决定下一步；不覆盖他人对同一字段的更新。 |

系统不会清空原邮箱垃圾箱，也不会为了移动一封邮件而批量清除其他待删除邮件。不同服务商的文件夹和标签机制可能不同，接入后应以当前服务商的实际结果核对。

真实来信可由经办人主动使用「AI 整理」，按下节完成复核与交接。收件本身不会自动调用模型；示例里的预置结果不代表真实来信已经整理。


## 整理来信并提交业务资料

**办理人**：持有邮件办理权限的业务经办人。使用 AI 还需助手使用权限。接收人是所关联客户、开发案或订单的业务负责人；发票资料交给其来源订单负责人。

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 在「智能邮箱」打开来信，核对发件人、正文与附件。 | 原邮件可读；附件需另行预览，不能只看 AI 摘要。 |
| 2 | 点击「AI 整理」，核对正文使用确认后点击「开始整理」。 | 平台模型仅处理此邮件的主题及最多 12000 字符正文。结果出现「待复核」；附件或正文截断会单独提示。 |
| 3 | 点击「复核资料」，逐项对照原文依据。修订不准确的值，取消不需要提交的条目，核对分类并填写必要备注。 | 原文依据保留。交期、数量、币种、单位、付款阶段以及“待确认”等限定语不丢失。 |
| 4 | 点击「保存复核」。 | 显示「已复核」及复核人。人工修订的条目有标识，正式业务单据尚未改变。 |
| 5 | 在「业务关联」选择正确对象并关联，再在「提交到业务对象」选择本次目标并提交。 | 资料快照交给业务负责人，其「我的工作 → 接着完成」出现处理事项。 |
| 6 | 负责人从待办打开原邮件，对照本次资料快照、原文与附件，到相应业务模块办理必要变更、提交或审批。 | 正式业务仍按相应模块权限及门禁办理；邮件复核不代替审批。 |
| 7 | 返回原邮件点击「记录处理结果」，选择「已处理」或「不适用」，填写处理说明并保存。 | 对应待办完成，原资料、经办人、处理说明及旧快照继续保留。 |

**交接前检查**：私人邮箱不会因为关联订单而自动分享。业务负责人必须为公司有效成员、具备邮件办理权限并有权查看此邮箱，才能接收资料；无权时，使用公司已授权的共享邮箱交接。不要为绕过提示而借用他人身份。

**复核后的修订**：点击「修改复核」后保存会形成新复核版本。已提交的快照不被改写；需要再次交接时，明确提交新版本。旧版尚待处理时，由原接收人在旧事项中记录其处理结论，不把新版本的结论误记到旧事项。

**完成标准**：「已复核」表示经办人核对了邮件整理结果；「已处理」表示负责人记录了该次交接的处理结论。两者都不表示订单已批准、发票已确认、货款已收到或款项已付。正式结果到对应业务单据核对。

## 使用 Agent 协助整理后的复核

Agent 可以在本人授权范围内读取邮件和整理资料、准备复核或处理提议。复核与处理结果经 Agent 办理时进入本人「接着完成」，本人查看邮件主题、字段值、原文依据和备注后，才点击「确认执行」。内容不符可拒绝，版本已经改变时应重新核对。Agent 无法代替本人确认自己的提议。

## 整理或交接未完成时

| 情况 | 处理方式 |
|---|---|
| 模型未配置或平台授权失效 | 联系平台管理员检查模型连接；不重复提交以代替配置处理。原邮件保留。 |
| 响应超时或格式、原文依据无法核实 | 原邮件与正式数据不变，稍后重试整理。未核实的结果不进入复核。 |
| 邮件原文或整理版本变化 | 关闭旧复核窗口，重新打开当前结果；必要时重新整理。 |
| 没有明确可提取字段 | 可复核分类，但不能提交空的业务资料。按原邮件内容人工办理。 |
| 已全部提交 | 当前复核版本已交给所选对象，不重复提交；有实质修订时先保存新复核版本。 |
| 业务负责人看不到此邮箱 | 核对共享邮箱成员与实际业务负责人，不通过私人邮箱强行交接。 |
| 无法勾选待办完成 | 邮件资料事项必须在原邮件中「记录处理结果」，不能只勾选完成而不留结论。 |


## Agent 准备回复草稿，由本人复核发送

**办理人**：邮箱有权经办人；Agent 使用本人的有效「可办理」连接。原邮箱已连接且具备发送能力。示例账号不能向真实邮箱投递。

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 让 Agent 读取当前来信和原始依据，按明确要求保存回复草稿。 | 草稿保存，不自动发出；不把客人提出的条件写成已经确认的承诺。 |
| 2 | 本人在「智能邮箱 → 草稿」打开该草稿，核对发件身份、收件人、主题和全文。 | 可见保存经办人及「经 Agent」标识。找不到时核对当前邮箱与文件夹。 |
| 3 | 内容需要调整时点击「继续编辑」，核对抄送、密送、附件和业务原件。 | 不凭文件名判断附件内容；确认价格、日期和付款承诺有准确依据。 |
| 4 | 点击「发送」，在确认窗口核对发件身份、全部收件人及附件数量。 | 确认前不会投递；取消保留草稿。 |
| 5 | 确认无误后点击「确认发送」。 | 成功时草稿移出草稿列表，并在「已发送」保留发送记录、经办人、时间和服务器结果。 |
| 6 | 打开已发送邮件读回结果；需要 Agent 接续时，让其读取同一已发送记录。 | 发件服务器接受、最终送达、对方已读分别判断，不能只凭聊天中的完成说明。 |

结果不确定或部分收件人被接受时，先到「待发送」核对原发送结果，不新建相同邮件重复投递。客户端重复读取或查询原操作不能代替核对发送状态。

当前标准 MCP 可保存草稿、读取本人可见的来信、草稿、已发送邮件及发送记录。可核对各收件人的服务器接受结果、最近一次发送观察；记录仍在发送中或结果不确定时，不把它当作已经完成。内容或名单显示不完整时，由本人回原记录核对，不能据截断资料作出承诺；实际 SMTP 发送由本人在智能邮箱的确认流程办理。不能调用仅服务端使用的发送结果命令来制造“已发送”记录。员工接手按本节进行，连接管理见[Agent连接与提议确认](agent-connections.md)。
