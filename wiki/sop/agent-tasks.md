# 长期 Agent 任务 SOP

适用于「我的账号 → 长期Agent → 任务」。任务用于交给已连接的外部 Agent 持续办理；安排任务后仍须连接并启动所选 Agent 客户端。关闭 Bambook 页面不停止已运行的外部客户端；关闭客户端则不会继续思考和办理。

## 岗位与开始条件

| 岗位 | 负责事项 |
|---|---|
| 公司管理员 | 在「公司管理 → Agent服务」配置服务名称、实际责任人及只读/可办理模式。责任人可以是业务员、专业岗位或管理者，无须是公司老板。 |
| 任务责任人 | 在本人账号启用所负责的连接，安排任务、提供当前业务目标，核对敏感提议与执行结果，暂停或停止任务。 |
| Agent 客户端 | 通过本任务连接读取当前授权资料，保存检查点，按业务门禁办理；需要本人确认时等待，不以任务说明代替审批。 |

责任人需仍属于该公司并具有助手使用及相应业务权限。任务不会增加岗位权限，也不会扩大客户、小组、邮箱或财务资料的可见范围。不要使用他人的账号或配置。

## 启用连接与安排任务

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 管理员配置 Agent 服务及实际责任人。 | 责任人本人可在「长期Agent → 连接」看到该服务。 |
| 2 | 责任人在「连接」启用凭据；已有有效连接可直接使用。 | 显示「凭据有效」。长期密钥管理与任务连接分开；不要把长期密钥贴入聊天或任务内容。 |
| 3 | 切换「任务」，点击「新建任务」。选择连接，填写简短名称及明确任务内容。 | 任务内容包括目标、准确对象、资料依据、允许动作及何时交回本人。未知价格、交期或付款不得让 Agent 自行编造。 |
| 4 | 点击「安排任务」。 | 新任务显示「待领取」。这仅表示已安排，没有假定执行器已经启动。 |
| 5 | 打开任务，点击「连接Agent → 生成任务连接 → 复制配置」。 | 得到本任务的 MCP 配置。仅交给本人选择的可信客户端，不公开分享。 |
| 6 | 在支持 HTTP MCP 的客户端中加入配置并启用连接，安排它读取任务内容后办理。 | 客户端开始实际业务调用后，任务显示「执行中」及最近心跳。公司和任务已绑定，无须再次选择。 |

同一时间每人最多安排十个未结束任务。每项任务有效期二十四小时，最多四十次业务工具调用、累计执行三十分钟。重新连接或暂停不会清零额度；任务状态查询、心跳及检查点不冒充新的业务操作。

## 跟进、人工确认与完成

| 状态或事项 | 负责人操作与判断 |
|---|---|
| 待领取 | 确认客户端已加入当前任务配置并开始办理。刷新页面不能代替启动客户端。 |
| 执行中 | 查看最近心跳、业务调用数量、检查点及过程记录。心跳只代表连接活动，不能证明业务已完成。 |
| 待本人确认 | 点击「查看待确认事项」，在「我的工作」打开对应 Agent 提议。核对对象、具体值及原始资料，再确认、拒绝或稍后处理。 |
| 本人确认后 | 客户端重新读取当前结果，再继续任务。确认单项业务不表示整项任务已结束。 |
| 本人拒绝后 | 客户端读取拒绝结果，按原因修正或结束。不要反复提出完全相同的错误提议。 |
| 执行结束 | 阅读「Agent执行报告」，回到原邮件、订单、审批或财务记录核对实际状态与回执。报告不是审批、到账或最终送达证明。 |
| 邮件待同步 | 在智能邮箱核对「原邮箱已同步」；移动结果不确定时先核对原操作，不能重复发起移动。任务不得把尚未同步的本任务操作报告为成功。 |

资料在提议后被其他人改动，系统可能拒绝按旧提议执行。先拒绝过时提议，让客户端重新读取再提出；不能为了继续而覆盖别人的新结果。

## 缺资料时补充答复

Agent 无法从现有资料确认价格、交期、数量、收付款依据等关键事实时，应先提问，不能猜测。任务显示「待补充资料」，问题会保留在同一任务内。

| 步骤 | 操作 | 结果与判断 |
|---|---|---|
| 1 | 进入「我的账号 → 长期Agent → 任务」，打开「待补充资料」的任务。 | 核对任务对象、Agent问题及原始依据。当前须在任务列表查看，不依赖尚未接入的首页提醒。 |
| 2 | 点击「补充资料」，填写答复并提交。 | 有准确依据时写清值及依据；尚未取得时明确要求保留原值、等待确认，不编造答案。 |
| 3 | 核对问题下的「本人答复」。 | 正常等待的任务返回待领取，由同一客户端读取答案再继续；暂停中的任务保持暂停，仍须本人明确点击「继续任务」。 |
| 4 | Agent提出修改、付款或发送等后续动作时，回原业务核对。 | 补充答复不是审批，也不自动确认Agent提议；敏感动作仍按原确认和岗位流程办理。 |

答复提交遇网络中断，保留原内容，用「核对原操作」核对，不另开相同答复。已停止或失去授权的任务不能补答；先核对原问题、已办结果和权限，再决定后续交接。每任务最多十个问题，问题最多两千字、答复最多四千字；暂停、回答或换连接不清零已有额度。

## 暂停、重新连接与停止

| 需要 | 操作 | 结果 |
|---|---|---|
| 暂时中断 | 打开任务 →「暂停任务」→确认。 | 当前执行被阻断，检查点、已用额度和已办业务保留。 |
| 继续原任务 | 暂停后选择「继续任务」并确认，再让客户端读取当前状态。 | 返回「待领取」，客户端可重新领取并从检查点接续；不会自行假定先前的操作成功。 |
| 客户端丢失或需更换连接 | 选择「连接Agent」重新生成配置，在可信客户端替换旧配置。 | 旧任务连接立即失效，正在运行的旧执行器被中断；检查点和已用额度保留。 |
| 不再办理 | 选择「停止任务」并确认。 | 不可再续办；该任务的待确认提议被拒绝。已经办理的业务和实际远端操作保留，不能靠停止任务撤销付款、邮件或订单变更。 |
| 客户端或服务器重启 | 重启后先读任务状态、检查点及原业务结果，再续办。 | 已保存检查点继续保留。原执行失去心跳后约九十秒可重新领取；仍有执行器占用时不要同时启动第二个。 |

暂停或停止无法追回已发到外部服务的请求。遇结果未知，先在原业务模块核对；需要处理已提交但因任务停止而阻断的邮件同步时，由当前有权员工核对后明确选择重试。

## 异常与交接

| 情况 | 处理 |
|---|---|
| 执行失败 | 核对执行报告和原业务记录。失败报告不证明此前没有写入；处理原因后另行安排所需任务。 |
| 权限已变化 | 先核对公司资格、岗位、小组、服务连接和资料范围。仍为公司有效成员、仅失去AI使用权限时，本人可查看任务基本状态、暂停或停止旧任务；在「我的工作」拒绝旧提议，在「长期Agent → 连接」撤销旧密钥。任务内容可能隐藏，不能继续执行或确认。恢复办理须重新核对权限与来源；不要反复生成旧配置。 |
| 连接已撤销或轮换 | 客户端使用本人重新生成的当前配置；不要继续使用旧配置反复尝试。 |
| 达到限额或已到期 | 先核对已办结果，再把剩余工作安排为新任务。新任务不会自动继承旧提议或未知结果。 |
| 页面提示操作未完成或网络中断 | 使用「核对原操作」检查原请求；不要反复建立相同任务或连续点击停止。 |
| 交给同事 | 提供准确业务编号、原始依据、已办结果和剩余事项，由同事按自己的权限接手；不转发自己的任务凭据。 |

当前由所选外部客户端实际执行任务；平台内部自动模型执行、定时巡检和异常主动通知不包含在本流程内。有效连接或心跳不表示这些能力已经启动。
