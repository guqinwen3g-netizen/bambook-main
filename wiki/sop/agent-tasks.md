# 长期 Agent 任务 SOP

适用于「我的账号 → 长期Agent → 任务」。新建时选择执行方式：「平台执行」由平台配置的模型在后台办理；「外部客户端」由本人连接并启动的可信 Agent 客户端办理。两种方式都使用本人的业务权限，不能代替公司岗位审批。

关闭网页不会停止平台任务。外部模式还依赖所选客户端持续运行。需要终止时，在原任务选择「停止任务」，不要用关闭页面代替停止。

## 岗位与开始条件

| 岗位 | 负责事项 |
|---|---|
| 公司管理员 | 在「公司管理 → Agent服务」配置服务名称、实际责任人及只读/可办理模式。责任人可以是业务员、专业岗位或管理者，无须是公司老板。 |
| 任务责任人 | 在本人账号启用所负责的连接，安排任务、提供当前业务目标，核对敏感提议与执行结果，暂停或停止任务。 |
| 执行方 | 平台模型或所选外部客户端读取当前授权资料，按业务门禁办理；缺资料或需要本人确认时等待，不以任务说明代替审批。 |

责任人需仍属于该公司并具有助手使用及相应业务权限。任务不会增加岗位权限，也不会扩大客户、小组、邮箱或财务资料的可见范围。不要使用他人的账号或配置。

## 启用连接与安排任务

| 步骤 | 操作 | 应看到的结果 |
|---|---|---|
| 1 | 管理员配置 Agent 服务及实际责任人。 | 责任人本人可在「长期Agent → 连接」看到该服务。 |
| 2 | 责任人在「连接」启用凭据；已有有效连接可直接使用。 | 显示「凭据有效」。长期密钥管理与任务连接分开；不要把长期密钥贴入聊天或任务内容。 |
| 3 | 切换「任务」，点击「新建任务」。选择执行方式和连接，填写简短名称及明确任务内容。 | 写清目标、准确对象、资料依据、允许动作及何时交回本人。未知价格、交期或付款不得让 Agent 自行编造。只读连接不能修改业务。 |
| 4 | 点击「安排任务」。 | 平台模式先显示「待执行」，领取后显示「执行中」；外部模式显示「待领取」。已安排不等于业务已办理。平台执行暂不可用时，先请管理员核对模型与服务，不反复创建相同任务。 |
| 5 | 仅外部模式：打开任务，点击「连接Agent → 生成任务连接 → 复制配置」。 | 得到本任务的 MCP 配置。只交给本人选择的可信客户端，不公开分享；平台模式不需要复制或发送长期密钥。 |
| 6 | 仅外部模式：在支持 HTTP MCP 的客户端中加入配置并启用，让它读取任务后办理。 | 客户端开始实际业务调用后，任务显示「执行中」及最近心跳。公司和任务已绑定，无须再次选择。 |

同一时间每人最多安排十个未结束任务。每项任务有效期二十四小时，最多四十次业务工具调用、累计执行三十分钟。重新连接或暂停不会清零额度；任务状态查询、心跳及检查点不冒充新的业务操作。

平台任务沿用安排时选择的界面语言生成报告，业务名称和原件文字保留；任务内容明确要求另一种输出语言时，以该要求为准。

## 跟进、人工确认与完成

日常从「我的工作」简报或右上角「通知」查看任务提醒；通知中心支持未读、全部与搜索。点击提醒会打开同一项任务，已读记录仍可从「全部」检索。提醒包含仍待处理及近期结束的任务；较早记录到「长期Agent → 任务」查询。

| 收到的提醒 | 下一步 |
|---|---|
| Agent待补充资料 | 打开原任务，阅读问题，点击「补充资料」，填写已有依据；确实没有依据就如实说明，不补造交期、价格或凭证。 |
| Agent待本人确认 | 从原任务查看待确认事项，核对准确对象、动作与影响，再确认或拒绝。阅读提醒不等于确认。 |
| Agent任务需处理 | 查看原任务的当前故障及已办记录。问题处理后选择「继续任务」，沿同一任务接续；不要重新安排同一笔业务。 |
| Agent执行结束或失败 | 查看报告并回原业务核对结果。核对结束不等于工厂已确认、货已发出或款已付出。 |
| 权限变化、到期或达到限额 | 按下方异常表处理，核对已办结果，避免旧配置继续办理。 |

标为已读不办理业务，不补答，也不恢复任务。同一问题暂停后不会再次变成新提醒；出现新问题或新的执行结果时会重新提醒。管理员管理Agent服务，不代替员工查看其个人任务提醒。

网页打开时会更新提醒；关闭网页不停止后台平台任务，返回后再读取最新状态。提示音沿用本人音量与通知偏好，首次进入不补播历史声音。当前不发送任务通知邮件或系统级推送。

| 状态或事项 | 负责人操作与判断 |
|---|---|
| 待领取 | 确认客户端已加入当前任务配置并开始办理。刷新页面不能代替启动客户端。 |
| 执行中 | 查看最近心跳、业务调用数量、检查点及过程记录。心跳只代表连接活动，不能证明业务已完成。 |
| 等待继续 | 查看「计划继续」及最近检查点。平台任务到时按原任务重新读取资料；外部客户端须保持运行或到时重新接续。无须提前点击继续，不另建相同任务。 |
| 等待资料变化 | 查看「等待资料」「等待截止」及最近检查点；可用「查看原资料」打开同一对象。资料变化或到达截止后，执行方须重新完整读取原件。 |
| 等待重试 | 平台保留原任务并稍后核对原步骤。不要另建相同任务或再次提交相同业务。 |
| 已暂停，提示模型故障 | 先核对已办结果，请管理员处理模型服务，再在原任务继续。连续故障会暂停，恢复不清零已用额度。 |
| 待本人确认 | 点击「查看待确认事项」，在「我的工作」打开对应 Agent 提议。核对对象、具体值及原始资料，再确认、拒绝或稍后处理。 |
| 本人确认后 | 执行方重新读取当前结果，再继续任务。确认单项业务不表示整项任务已结束。 |
| 本人拒绝后 | 执行方读取拒绝结果，按原因修正或结束。不要反复提出完全相同的错误提议。 |
| 执行结束 | 阅读「Agent执行报告」，回到原邮件、订单、审批或财务记录核对实际状态与回执。报告不是审批、到账或最终送达证明。 |
| 邮件待同步 | 在智能邮箱核对「原邮箱已同步」；移动结果不确定时先核对原操作，不能重复发起移动。任务不得把尚未同步的本任务操作报告为成功。 |

资料在提议后被其他人改动，系统可能拒绝按旧提议执行。先拒绝过时提议，让客户端重新读取再提出；不能为了继续而覆盖别人的新结果。

「执行结束」是本次 Agent 任务结束。订单是否批准、QC是否放行、款项是否到账、原邮箱是否同步，仍到对应业务记录核对。本人确认 Agent 提议也不会跳过主管、QC、财务或原单据的资料门禁。

## 缺资料时补充答复

Agent 无法从现有资料确认价格、交期、数量、收付款依据等关键事实时，应先提问，不能猜测。任务显示「待补充资料」，问题会保留在同一任务内。

| 步骤 | 操作 | 结果与判断 |
|---|---|---|
| 1 | 进入「我的账号 → 长期Agent → 任务」，打开「待补充资料」的任务。 | 核对任务对象、Agent问题及原始依据。也可从「我的工作」或任务提醒打开同一任务。 |
| 2 | 点击「补充资料」，填写答复并提交。 | 有准确依据时写清值及依据；尚未取得时明确要求保留原值、等待确认，不编造答案。 |
| 3 | 核对问题下的「本人答复」。 | 正常等待的任务由原执行方读取答案再继续；暂停中的任务保持暂停，仍须本人明确点击「继续任务」。 |
| 4 | Agent提出修改、付款或发送等后续动作时，回原业务核对。 | 补充答复不是审批，也不自动确认Agent提议；敏感动作仍按原确认和岗位流程办理。 |

答复提交遇网络中断，保留原内容，用「核对原操作」核对，不另开相同答复。已停止或失去授权的任务不能补答；先核对原问题、已办结果和权限，再决定后续交接。每任务最多十个问题，问题最多两千字、答复最多四千字；暂停、回答或换连接不清零已有额度。

## 约定时间后继续

在任务内容里写清要核对的准确对象、下一次核对时间以及结束条件。执行方可在原任务等待至该时间；任务显示「等待继续」和「计划继续」。平台任务到时自行接续；外部模式仍需可信客户端运行。

等待不会延长任务到期或补回额度。需要暂停时可正常暂停，恢复仍保留原定时间；需要取消就停止任务。服务重启后也不重新计时。到时必须重新读取原资料，不能把等待前的状态当作最新结果。新邮件/查询订阅与周期巡检另行接入。

只要求在指定时刻复核时，在任务内容中写清日期、时间和时区，例如“北京时间11月2日9点再核对”。资料变化不应提前触发该任务；打开任务应看到「等待继续」和「计划继续」。

## 关注原资料变化

适用于已有订单、邮件或其他原记录的后续核对。例如等订单状态变化后，再判断是否具备下一步条件。它不代表已订阅新的客户回信，也不自动批准采购、付款或出运。

| 步骤 | 操作 | 结果与判断 |
|---|---|---|
| 1 | 新建任务，选择执行方式和本人连接；写清准确业务编号、关注的变化、等待截止及何时交回。 | 例如“关注订单SO-G-…的审批状态；完整读取当前订单，等原件变化或今天17点再核对。未批准前不采购，任何修改先交本人确认”。 |
| 2 | 安排后，执行方先完整读取当前原件。 | 能建立原件基线后，任务显示「等待资料变化」；缺资料或原件无法完整读取时，应补充依据或交回，不能猜测。 |
| 3 | 打开任务，核对「等待资料」和「等待截止」。需要时点击「查看原资料」。 | 应是同一份原记录；等待不会占住模型办理位置，也不会改变业务。 |
| 4 | 原记录变化或到达截止后，查看「继续原因」和后续报告。 | “资料已变化”只说明需要重核；“到达最晚时间”不表示审批已通过或业务条件已满足。执行方仍须完整重读同一原件，再按真实业务门禁办理。 |
| 5 | 暂时不继续时暂停；需要接续时在原任务明确继续；不再关注时停止。 | 暂停、重连和服务重启保留原基线及截止，停止后不会到时复活；原任务和已办结果保留。 |

「等待截止」是转入接续核对的时间边界，实际执行仍受排队、有效授权和资料门禁约束。没有变化时也应如实报告，不能把截止当成客户、工厂或管理者的业务确认。重新看列表、查任务状态或阅读另一份资料，都不能代替重读本次关注的原件。

完整读取涵盖当前授权原记录的文字、字段及可读取明细，附件和图片内容仍需另行核对。遇原件超出单次读取范围，Agent应明确交回未读部分；本人按准确业务编号回原模块核对并提供依据。部分内容不能当作完整原件，也不能据此确认业务已办理。

## 暂停、重新连接与停止

| 需要 | 操作 | 结果 |
|---|---|---|
| 暂时中断 | 打开任务 →「暂停任务」→确认。 | 当前执行被阻断，检查点、已用额度和已办业务保留。 |
| 继续原任务 | 暂停后选择「继续任务」并确认，再让客户端读取当前状态。 | 平台任务返回待执行，外部任务可重新领取；若原定时间尚未到，则保持「等待继续」及原时间。不会自行假定先前的操作成功。 |
| 客户端丢失或需更换连接 | 选择「连接Agent」重新生成配置，在可信客户端替换旧配置。 | 旧任务连接立即失效，正在运行的旧执行器被中断；检查点和已用额度保留。 |
| 不再办理 | 选择「停止任务」并确认。 | 不可再续办；该任务的待确认提议被拒绝。已经办理的业务和实际远端操作保留，不能靠停止任务撤销付款、邮件或订单变更。 |
| 客户端或服务器重启 | 先读原任务状态、检查点及原业务结果，不重复安排。 | 平台服务恢复后按原任务接续，暂停中的任务仍暂停；外部客户端须重新运行。原执行失去心跳后约九十秒可重新领取，仍有执行器占用时不要同时启动第二个。 |

暂停或停止无法追回已发到外部服务的请求。遇结果未知，先在原业务模块核对；需要处理已提交但因任务停止而阻断的邮件同步时，由当前有权员工核对后明确选择重试。

本人已经确认的邮件操作以本人的授权继续处理；停止原 Agent 不会撤销这项确认。有关原邮箱操作未完成时，Agent不能仅凭本地文件夹改变报告成功。

## 失败时核对原操作

1. 在「我的账号 → Agent 操作记录」按经办人、时间和动作找到原记录，打开详情。
2. 核对目标业务及修改前后的值。需要精确定位时，点击「复制操作编号」；编号也会显示在可选取的只读框中。
3. 让本人信任的 Agent 按原编号查询回执，并回到原邮件、订单或财务记录核对当前结果。只提供操作编号和必要业务依据，不转发连接凭据或密码。
4. 已确认、已拒绝或已办理的操作先核对现有结果。不要为了重试换成新编号再次提交，也不要在原编号下更换业务内容。

## 异常与交接

| 情况 | 处理 |
|---|---|
| 执行失败 | 核对执行报告和原业务记录。失败报告不证明此前没有写入；处理原因后另行安排所需任务。 |
| 权限已变化 | 先核对公司资格、岗位、小组、服务连接和资料范围。仍为公司有效成员、仅失去AI使用权限时，本人可查看任务基本状态、暂停或停止旧任务；在「我的工作」拒绝旧提议，在「长期Agent → 连接」撤销旧密钥。任务内容可能隐藏，不能继续执行或确认。恢复办理须重新核对权限与来源；不要反复生成旧配置。 |
| 连接已撤销或轮换 | 客户端使用本人重新生成的当前配置；不要继续使用旧配置反复尝试。 |
| 达到限额或已到期 | 先核对已办结果，再把剩余工作安排为新任务。原任务不会自行重置额度或重新办理，也不会挡住其他待执行任务。新任务不会自动继承旧提议或未知结果。 |
| 页面提示操作未完成或网络中断 | 使用「核对原操作」检查原请求；不要反复建立相同任务或连续点击停止。 |
| 交给同事 | 提供准确业务编号、原始依据、已办结果和剩余事项，由同事按自己的权限接手；不转发自己的任务凭据。 |

当前支持上述平台执行及外部客户端的一次业务委托、本人补充/确认及界面内提醒。新邮件/查询订阅、周期巡检与系统级推送仍待接入，不能因为凭据有效或有心跳就认为这些功能已经启动。
